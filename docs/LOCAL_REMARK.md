# 本机备注覆盖试验（4.1.15.56）

用户目标：好友原昵称 CCCCC 不变，手机显示已设备注 A，电脑独立显示自定义 B。
这与修改无备注好友的 nick_name 不同，本实现针对已经有备注的普通好友。

## 操作

1. 微信已登录时打开工具、读取联系人，选择有备注 A 的测试好友。
2. 在右侧输入电脑显示文字 B，点击“本机备注覆盖试验”。
3. 看清试验提示，完全退出微信及托盘后确认。工具自动备份、只在副本中检查，再单次试写并开始采集。
4. 登录电脑微信检查名称，并查看手机是否仍显示 A。点击“结束备注诊断并复制报告”后粘贴报告，另说明实际显示结果。

无需命令行或重新选择图片。A/B 配置与头像配置独立保存，重新打开选中好友即可复用 B。
“恢复电脑原备注缓存”会以同样的安全门槛写回保存的 A，不删除联系人。
“清除本机备注配置”只删除工具配置，不修改微信；“备注故障恢复”只恢复可识别的未完成操作。

## 实现

- 仅 `UPDATE contact SET remark=? WHERE username=?`，不修改 nick_name、wxid、标志、拼音、额外缓冲区或同步队列。
- 不点击微信官方备注界面，不调用备注提交 API，不安装服务、Hook 或常驻进程。
- 对 main/WAL/SHM 使用与头像后端相同的独占锁、加密校验、完整备份、事务副本、逐文件写回、失败回滚。
- 比较目标完整行，除 remark 外必须保持原值；比较所有非目标联系人及 contact.db 中其他数据表的数据摘要。
- 未知目标表触发器、非普通好友、无原始备注、缺失或重复记录、格式/版本不匹配均拒绝。
- 版本仅开放 4.1.15.56，所有写入均要求本次进程内、指定账号/目标/文字/策略/来源三文件绑定的单次副本证明。
- 头像库与联系人库的路径校验、备份目录、配置、恢复入口分开；禁止删除联系人记录。
- 采样最多约三分钟，报告只含版本、相对时间及变化布尔值，不含姓名、备注、身份、原始哈希、路径或密钥，不自动上传。

## 验证边界

代码可以证明工具仅定向修改本机联系人缓存，并在该次写回前后保留其他字段与数据表。
这不能证明微信重新登录、联网、同步时不会上传或覆盖该变化；保留同步字段不等于已经理解同步协议。
不应直接把本构建用于重要联系人；先用测试联系人检查“电脑 B，手机 A”，并重启/重新联网复核。
`client_rendering_verified` 和 `remote_non_sync_verified` 在报告中均保持 false，不能用配置存在或缓存一致冒充验收。
若手机备注变化，应停止本试验；“恢复电脑缓存”不是服务器资料恢复功能。
客户端搜索、拼音索引、会话标题、资料页是否均显示 B，及服务器端保持 A，均尚未实测。
