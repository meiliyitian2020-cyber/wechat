# 纯本地昵称：独立可行性结论

状态：未实现原版微信客户端的纯本地昵称替换，禁用写入。头像实测结果不能迁移为昵称结论。

## 本轮核查

- WeChatMsg 固定版本 `14b466dcc4c60b43d9d79301e489c8d6029daed4`：
  `wxManager/db_v4/contact.py::set_remark` 直接修改打开的 SQLite `contact.remark`。
  它不是专用的本机显示字段，也没有证明原版微信启动后不上传该变化；不能复用为已验证纯本地后端。
- wechatauto-replica 固定版本 `d322c4a9b1124228820bab363e5676016f188fc6`：
  `wechatauto/db.py::get_nickname` 在读取端采用 `remark or nick_name or user`；
  `wechatauto/remark.py::set_remark` 通过客户端备注界面点击完成。这是正常备注修改流程，不符合本项目的纯本地要求。
  两者都没有提供能够验证远端不变化的本机昵称替换实现。
- wechat-local-viewer 固定版本 `de6a3f09fab43a02e786826b3085545dec9615f0`：
  联系人与会话名称是独立查看器读取结果，不能证明原版微信窗口的实际显示路径。
- 本项目 `editor/reader.py::contacts` 只读取 `username,nick_name,remark`；
  `editor/gui.py` 禁用昵称输入框；没有原始 contact.db 写入后端。

## 障碍与不能作出的推断

`nick_name` 是联系人昵称缓存，`remark` 是备注缓存；尚未找到并验证只作用于本机的独立别名字段。
仅改 nick_name 是否控制备注优先的会话标题、聊天窗口、资料页，还没有真实客户端证据。
直接修改 remark 即使未调用官方接口，也不能据此保证微信后续不会同步；离线修改不能证明重联后的行为。
不允许以“未主动联网”“数据库字段一致”“工具界面名字变化”作为纯本地且客户端生效的验收证据。
会话表的 last_sender_display_name/summary 也不能冒充好友全局身份字段，不能据此批量改聊天记录。

## 当前允许与禁止的边界

保留头像功能；昵称仍禁用，不调用上游备注 UI 操作，不尝试在真实好友资料中盲写 remark、标志位或队列表。
没有证据表明这在技术上绝对不可能；结论是当前没有经过验证、符合用户约束的实现。
继续开启原库昵称试写前，需要受控测试账号与真实客户端的读写/同步证据；至少独立验证实际名称显示、
退出工具后保留、重新联网和双端重新登录后其他设备名字不变，以及服务器资料未发生修改。
当前 Linux 环境不能执行该验收，现有摘要报告也不能提供这些证据。
